为内部合成记录编写字段披露选择器，在满足证明义务的同时校验各接收方的视图。一次请求有若干接收方，每方声明允许字段集合及必须满足的证明义务；义务可以由多种字段组合之一构成。字段存在依赖，比如披露详细状态必须附分类标签；依赖可成环，必须取闭包。字段还声明可选的互斥组，组内至多提交一个字段。在同一发布批里，不同接收方收到不同视图；审查另给可能串阅的接收方组，组看到其成员字段并集。某些字段组合规定禁止同一接收方或任一串阅组完整看到，单个字段本身可合法。签发同一字段给不同人有各自成本，共用封装模板另有一次开销。
plan 要求先最小化所有接收方字段发放成本加不同模板开销，再最小化发放字段总数，最后按接收方 ID 排序的字段 ID 列表决胜。一个模板由完全相同的字段集合唯一标识；同一集合出现多次只收一次固定开销。check 对给定计划返回违反的第一条约束并附串阅来源。支持 8 个接收方、22 字段；说明怎样枚举合法的闭合视图并保持最优性，含零成本字段可能通过模板共享改变最优解的情况。测试覆盖依赖环、两个视图分别合规但串阅违规、共用模板反转局部最优、禁止含空组合的输入和无法覆盖义务。所有法域和字段均为虚构，规则完全取自输入。

README 应让复核人能按命令复现披露视图，包括完整输入输出定义和可直接运行的样例。用 `python -m solution <命令> CASE.json` 执行，涉及持久状态的命令需带 `--db DB.sqlite`。标准输出采用 UTF-8 JSON，同一逻辑输入的决定应一致；结构错误报告错误码及具体字段位置。实现从空仓库起步，采用 Windows 原生 Python 3.12、标准库和 CPU，夹具均使用本地虚构数据。断言测试通过 `python -m unittest discover -s tests -v` 运行。
